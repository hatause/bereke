# Bereke Operator Academy — архитектура этапа 1

## Границы

Один локальный учебный профиль и четыре дня обучения. Учебные экраны включают уроки, прогресс, Dashboard, словарь, вопросы к тренеру и настройки темы. CRM позволяет просматривать вымышленные продукты и вести учебные тикеты. Экзамены и Roleplay описаны в плане следующих этапов.

## Структура

```text
for codex/
  backend/
    app/
      config.py       # абсолютный путь SQLite, чтение .env
      db.py           # engine, PRAGMA, session per request
      models.py       # 25 доменных/служебных таблиц
      crm.py          # карточка клиента, очередь и команды тикетов
      schemas.py      # Pydantic контракты
      services.py     # агрегация уроков и прогресса
      main.py         # маршруты, локальная граница HTTP
      seed.py         # явный транзакционный импорт
    migrations/      # версии схемы и защита публикации вопросов
    tests/
  frontend/
    src/
      api.ts          # типы DTO и HTTP boundary
      components.tsx  # Panel, QueryState, SourceCitation, LessonCard
      App.tsx         # shell и экраны этапа 1
      theme.ts
      styles.css      # токены и адаптивная раскладка, Tailwind
    e2e/
  scripts/            # setup/start/privacy/audit
  docs/
  data/               # приватный пакет, исключён из Git
  sources/private/    # неизменённые оригиналы, исключены из Git
  .local/             # БД, извлечения, изображения, исключены из Git
```

## Поток данных

Браузер → React Router → TanStack Query → `/api` через Vite proxy → FastAPI → сервис → SQLAlchemy session → SQLite. У frontend нет импортов из `data` или `sources`. Статические файлы backend не раздаёт. Полные документы и изображения не выдаются API; наружу возвращаются только выбранные учебные формулировки и библиографические ссылки.

SQLAlchemy 2.x и Pydantic 2 используются напрямую, без SQLModel. Синхронные обработчики FastAPI подходят для одного локального пользователя. SQLite включает FK, WAL, busy_timeout. Миграции выполняются отдельно до запуска; `create_all` при старте приложения не используется. `GET /api/health` проверяет БД и наличие версии миграции.

## Состояние и ошибки

| Состояние | Где хранится | Почему |
|---|---|---|
| Отметки разделов | SQLite, LearningProgress | Перезапуск процесса не теряет данные |
| Агрегаты Dashboard | Вычисляются из БД | Нет расходящихся копий счётчиков |
| Серверные DTO | TanStack Query | Кэш с инвалидированием после успешного PUT |
| Тема | localStorage | Не зависит от сетевого запроса |
| Поисковая строка | React state | Временное состояние формы |
| Старое упражнение из чата | ImportRecord | Неполные сведения не превращаются в выдуманные ответы |
| Будущая попытка экзамена | ExamAttempt + AttemptQuestion + ExamAnswer | Порядок, снимок версии, ответы и позиция переживают обновление |
| CRM | Customers, продукты, SupportTicket и TicketEvent | Продукты доступны для чтения. Изменения тикета и журнал сохраняются в одной транзакции |

PUT передаёт желаемое состояние, а не команду toggle. SQLite UPSERT по `(user_id, section_id)` исключает дубли при повторном запросе. Отметка меняется в UI только после сохранения и повторного чтения. При ошибке виден текст ошибки; нет ложного уведомления об успехе. Параллельные вкладки используют последнее сохранённое значение, запрос обновляется при возвращении фокуса.

## Контент и достоверность

`verified` означает «формулировка сверена с предоставленной лекцией», а не «сегодня действует в банке». `disputed`, `historical`, `unverified` не допускаются к публикации ключа вопроса. SQLite-триггеры проверяют ссылку и статус источника; при отзыве подтверждения опубликованные вопросы переводятся в retired. Проверка самой педагогической формулировки и правильности вариантов остаётся обязанностью ревьюера будущего банка вопросов.

Отсутствующая дата остаётся NULL и отображается как «в источнике не указана». Отсутствующая информация обозначается «В лекциях этого нет». Не восстанавливаем год по дате файла. Противоречия не разрешаются автоматически. Изменение пакета seed требует отдельной миграции контента; повторный seed с тем же SHA256 сохраняет прогресс.

## Локальная безопасность

Сервера слушают только 127.0.0.1. Vite разрешает чтение только внутри frontend и запрещает приватные шаблоны путей. Backend проверяет Host и Origin для изменений. Это локальный single-user режим без пароля; для сетевого или многопользовательского развёртывания обязательны аутентификация, авторизация и отдельное проектирование. Включать 0.0.0.0 без этих изменений нельзя.

Ни PIN, ни CVV, ни кодовое слово, ни ИИН/IBAN/PAN не имеют колонок в синтетической CRM. DEMO-идентификаторы не являются банковскими реквизитами. Полнотекстовые извлечения и оригиналы никогда не используются seed как источник клиентских данных. Отчёты аудита описывают проблемы без переноса персональных данных со скриншотов.

## Масштабирование

При росте сначала выделить `features/learning`, `features/exams`, `features/crm` внутри монолита; разделить App.tsx по экранным модулям. PostgreSQL потребует замены SQLite UPSERT/PRAGMA и триггеров, проверки JSON и дат, миграционного теста. Факты и версии вопросов сохраняют историю. Микросервисы, очередь задач, Redis и внешняя LLM для этапа 1 не нужны.
