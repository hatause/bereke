# Задание для Codex: Bereke Operator Academy

Ты выступаешь как команда senior-разработчиков: software architect, frontend developer, backend developer, UI/UX designer, QA engineer и специалист по образовательным платформам.

Создай полноценное локальное веб-приложение Bereke Operator Academy. Это учебная система для подготовки оператора контакт-центра Bereke Bank (Казахстан) к экзамену и практической работе.

Проект должен быть функциональным, красивым, быстрым и удобным. Не ограничивайся дизайном, прототипом или набором статичных экранов.

## 1. Сначала изучи проект

Перед разработкой обязательно прочитай:

- AGENTS.md
- CODEX_TASK.md
- README_IMPORT.md
- data/manifest.json
- data/lessons_seed.json
- data/terms_from_excel.json
- data/exam_state_from_chat.json
- Все PDF, PPTX и XLSX в sources/private/

Изучи содержимое четырёх дней обучения и дополнительных материалов. Проверяй текст, таблицы и изображения внутри документов. Если PDF состоит из изображений, используй доступный способ просмотра страниц.

Составь внутренний реестр знаний: тема, факт, источник, номер страницы, дата действия, статус проверки.

Оригинальные лекции имеют приоритет над подготовленными JSON-данными. Если данные противоречат друг другу, не выбирай правильную версию самостоятельно. Добавь запись на страницу «Требует проверки у тренера».

Не придумывай условия Bereke Bank, тарифы, лимиты, процедуры идентификации и правила работы оператора. При недостатке данных показывай «В лекциях этого нет».

## 2. Технологический стек

Frontend:
- React + TypeScript + Vite.
- Tailwind CSS и качественная библиотека UI-компонентов.
- React Router.
- TanStack Query для API-запросов.
- Адаптивная верстка.
- Светлая и тёмная темы.

Backend:
- Python + FastAPI.
- SQLAlchemy и Pydantic.
- SQLite для локальной базы.
- Alembic для миграций.
- REST API с валидацией данных.

Тестирование:
- Pytest.
- Vitest.
- Playwright для основных пользовательских сценариев.

Приложение должно запускаться локально без платных сервисов, внешних API и настоящих банковских учётных записей.

## 3. Визуальный стиль

Создай оригинальный интерфейс уровня качественного fintech SaaS-приложения.

Основная тема: белый фон, зелёные акценты, нейтральные поверхности, аккуратные таблицы и понятная типографика.

Тёмная тема: графитовые поверхности, контрастный текст и приглушённые зелёные акценты.

Требования:
- Левое меню с разделами и иконками.
- Верхняя панель с поиском и переключением темы.
- Dashboard с карточками и графиками.
- Анимации переходов, загрузки и изменения состояния.
- Скелетоны, состояния ошибок и пустые состояния.
- Поддержка мобильных устройств.
- Удобная клавиатурная навигация.
- Единая дизайн-система компонентов.

Не копируй настоящие внутренние CRM Bereke Bank. Создай самостоятельную учебную систему, вдохновлённую общими принципами банковского интерфейса.

Не используй декоративные элементы в ущерб читаемости.

## 4. Главная страница Dashboard

Показывай:
- Общий прогресс обучения.
- Прогресс по четырём дням.
- Количество пройденных тестов.
- Средний результат.
- Последние ошибки.
- Слабые темы.
- Рекомендации по повторению.
- Историю учебных попыток.
- FCR, AHT, CSI, %Quality, Happy Clients.

Учебные показатели должны иметь отметку «Демонстрационные данные». Рассчитывай фактическую статистику тестов из сохранённых ответов пользователя.

## 5. Раздел «Обучение»

Создай четыре курса.

День 1. Welcome Day:
ценности Bereke Bank, роль оператора, клиентский сервис, метрики, стандарты общения, этапы диалога, структура контакт-центра.

День 2. Карточные продукты:
ALL IN, мобильное приложение, выпуск карт, условия открытия, документы, доставка, ошибки и ограничения.

День 3. Депозиты и переводы:
виды депозитов, процентные ставки, SWIFT, банковские переводы, B-Bonus+, MCC, Solar и бонусные лимиты.

День 4. Кредиты:
виды кредитов, погашение, ГЭСВ, ЕП, ЧДП, ПДП, просрочки, collection, условия кредитования и посткредитное обслуживание.

Для каждого дня создай:
- Краткую лекцию из 5–8 смысловых блоков.
- Главные факты.
- Таблицы цифр и условий.
- Пошаговые алгоритмы.
- Примеры из работы оператора.
- Список связанных терминов.
- Блок «Что выучить дословно».
- Блок «Что достаточно понимать».
- Кнопку повторения.

У каждого значимого банковского правила показывай ссылку на источник: название файла и страницу или слайд.

## 6. Центр тестирования

Реализуй минимум 15 проверенных вопросов на каждый день обучения.

Типы вопросов:
- Один правильный ответ.
- Несколько правильных ответов.
- Верно или неверно.
- Открытые вопросы.
- Практические ситуации с клиентом.

Функциональность:
- Один вопрос на экране.
- Сохранение ответа.
- Объяснение после ответа.
- Прогресс теста.
- Промежуточный результат каждые 5 вопросов.
- Итоговая оценка.
- История попыток.
- Повторение ошибок.
- Статистика по темам.
- Перемешивание вопросов и вариантов.

Создай итоговый экзамен из 40 вопросов, по 10 на каждый день.

Для открытых вопросов используй проверяемые критерии и образцы ответа. Если объективная автоматическая оценка невозможна, отмечай ответ для самостоятельной проверки, а не выставляй произвольный балл.

Каждый вопрос должен иметь:
- ID и тему.
- Правильный ответ.
- Объяснение.
- Сложность.
- Файл-источник.
- Страницу или слайд.
- Статус проверки.

Если для темы недостаточно подтверждённых данных, не выдумывай вопрос. Отмечай его как требующий проверки.

Вопросы являются тренировочными. Не называй их официальными вопросами Bereke Bank.

## 7. Учебная CRM

Создай работающую CRM с вымышленными клиентами.

Главная таблица клиентов:
- Учебный идентификатор.
- ФИО.
- Сегмент.
- Карты.
- Счета.
- Депозиты.
- Кредиты.
- Статус обращения.

Добавь поиск, сортировку и фильтры.

При открытии карточки клиента отображай вкладки:
- Обзор.
- Счета.
- Карты.
- Транзакции.
- Депозиты.
- Кредиты.
- Лояльность.
- Обращения.

Добавь демонстрационные сценарии:
- Не проходит платёж.
- Ошибка входа в приложение.
- Клиент интересуется выпуском ALL IN.
- Перевод находится в обработке.
- Не начислились бонусы.
- Клиент спрашивает о депозите.
- Клиент хочет погасить кредит.
- Клиент спрашивает о просрочке.

Реализуй работающие учебные действия: создание обращения, изменение его статуса, проверка демонстрационных транзакций и просмотр истории взаимодействий.

Система должна сохранять изменения в SQLite через FastAPI.

Все клиенты, номера, балансы и операции полностью вымышленные. Не используй реальные ИИН, банковские реквизиты, PIN, CVV или кодовые слова.

## 8. Симулятор работы оператора

Создай интерактивные ролевые диалоги.

Приложение играет роль клиента. Пользователь играет роль оператора.

Характеры клиентов:
- Спокойный.
- Раздражённый.
- Спешащий.
- Растерянный.

Диалог идёт по одной реплике.

Для работы без внешнего AI реализуй сценарное дерево с несколькими вариантами развития диалога и вводом ответа оператором.

После завершения оцени:
- Приветствие.
- Выяснение проблемы.
- Эмпатию.
- Точность информации.
- Соблюдение известных из лекций правил.
- Завершение разговора.

Покажи ошибки, пример улучшенного ответа и общий результат. Не используй выдуманные банковские процедуры для оценки.

## 9. Банковский словарь

Загрузи все термины из data/terms_from_excel.json.

Создай:
- Поиск по терминам.
- Фильтрацию по темам.
- Учебные карточки.
- Избранное.
- Проверку знаний.
- Прогресс запоминания.
- Повторение ранее изученного.

Распредели термины по дням, ориентируясь на соответствующие темы. Не теряй термины, не изменяй исходные определения без явной пометки.

## 10. Проверка спорных данных

Создай отдельную страницу «Проверка у тренера».

Обязательно добавь уже выявленные расхождения:
- Возраст женщин для кредитования: 60 или 61 год.
- Разные диапазоны просрочки soft collection.
- Порог нотариального согласия супруга: от 3,5 млн или свыше 3,5 млн тенге.
- Неясное обозначение «ставка 1/2» для досрочного закрытия депозита.
- Условия автоматического подключения и подключения конкретной карты к B-Bonus+.

Для каждой записи показывай исходные формулировки, источники, статус и поле для комментария тренера.

Спорные условия не должны использоваться как бесспорные правильные ответы экзамена.

## 11. Архитектура и качество

Создай понятную структуру frontend, backend, database, tests, scripts и documentation.

Реализуй модели данных, миграции, сидирование базы и API-эндпоинты. Подготовь документацию по API.

Условия готовности:
- Все страницы открываются.
- Навигация работает.
- Поиск клиентов возвращает результаты.
- Прогресс сохраняется после перезапуска.
- Тесты проверяют ответы.
- Статистика пересчитывается.
- Симулятор имеет рабочие сценарии.
- Светлая и тёмная темы работают.
- Не возникает ошибок TypeScript и Python.
- Нет ошибок в браузерной консоли в основных сценариях.
- Приватные файлы не доступны через публичные маршруты приложения и не попадают в Git.

Проверь сценарии через Pytest, Vitest и Playwright. Исправь найденные ошибки.

## 12. Порядок работы

Этап 1. Изучи источники, составь реестр фактов и противоречий.

Этап 2. Создай архитектуру, базу данных, API и работающее MVP.

Этап 3. Реализуй дизайн, Dashboard, обучение, тестирование и словарь.

Этап 4. Добавь CRM и ролевой симулятор.

Этап 5. Проверь качество контента и соответствие исходным материалам.

Этап 6. Запусти автоматические тесты, исправь ошибки и проверь основные пользовательские сценарии.

Этап 7. Создай README.md с точными командами установки и запуска под Windows и macOS.

Не останавливайся после составления плана. Переходи к реализации и выполняй этапы последовательно. Не оставляй заглушки вместо заявленных основных функций. Если среда не поддерживает необходимую проверку, прямо укажи, что именно не удалось проверить.

После работы предоставь:
- Структуру проекта.
- Список реализованных функций.
- Команды запуска.
- Результаты тестов.
- Список неподтверждённых банковских правил.
- Перечень оставшихся технических задач.

Главная цель: получить законченную локальную учебную систему, через которую я смогу проходить лекции, тренироваться, отвечать клиентам и готовиться к экзамену оператора Bereke Bank.
