# Bereke Operator Academy

Локальный учебный симулятор: React + TypeScript + Vite + Tailwind + React Router + TanStack Query; FastAPI + SQLAlchemy 2 + Pydantic 2 + SQLite + Alembic. Оригиналы лекций остаются приватными. Проект ничего не публикует и не обращается к банковским системам.

Работают Dashboard, четыре урока (22 раздела), сохранение отметок в SQLite, словарь с поиском (64 термина), 15 вопросов к тренеру, светлая и тёмная темы. CRM Simulator включает шесть вымышленных клиентов, карточки продуктов, очередь тикетов и журнал действий.

## Требования

- Python 3.12+ (проверено на 3.13.3).
- Node.js 22.12+ (проверено на 22.16.0), npm.
- Для первого скачивания зависимостей нужен интернет; при работе приложения внешние сервисы не нужны.
- Для наполнения нужен локальный `data/reviewed_content.json`, он уже создан в этой папке. `data/`, оригиналы и БД исключены из Git. Копия одного Git-репозитория без приватного пакета не содержит учебных данных: seed остановится с ясной ошибкой. Сохраняйте пакет отдельно, локально.

Скопируйте папку проекта вместе с приватным `data` локально, установите Python 3.12+ и Node.js 22.12+. Из корня проекта:

```bash

```

В двух терминалах:

```bash

```

## Рабочий сценарий

В разделе **CRM Simulator** найдите `DEMO-CUSTOMER-002`. В карточке доступны учебные счёт, карта, депозит и движения. Выберите тему «Депозит», создайте тикет, возьмите его в работу и отметьте решённым. Проверьте смену статусов в журнале и найдите тикет в очереди по статусу «Решён». Для повторной отработки откройте тот же тикет снова. Тикеты и журнал сохраняются в SQLite.

При обновлении с этапа 1 запустите setup из корня проекта перед перезапуском backend. Миграция CRM сохраняет существующий учебный прогресс и стартовые тикеты.

### Обучение

1. Откройте Обучение → Welcome Day.
2. Нажмите «Отметить прочитанным» у раздела. Дождитесь «Прогресс сохранён в SQLite».
3. Перезагрузите страницу или перезапустите backend: отметка остаётся.
4. В Обзоре отображается обновлённый счётчик. Кнопка «Снять отметку о прочтении» сохраняет обратное изменение.

Если backend недоступен, показывается ошибка и кнопка повторной загрузки. Отметка не считается сохранённой до успешного ответа. Прочтение не приравнивается к сдаче теста.

## Конфигурация и данные

`.env` необязателен; образец — `.env.example`. По умолчанию используется абсолютный путь `.local/academy.sqlite3`, независимо от текущей директории запуска backend. DATABASE_URL позволяет указать другую локальную SQLite БД.

`python -m app.seed` из backend повторяем: не обнуляет прогресс и не создаёт дубли. Если reviewed_content изменён, seed остановится — требуется версия миграции контента. Приватные данные не копируются в frontend/dist. Серверы слушают только 127.0.0.1. Не используйте этот single-user режим для доступа из сети.

Для резервной копии: остановите backend, скопируйте `.local/academy.sqlite3`, приватный каталог `data` и отдельно `sources/private` в защищённую локальную папку. При остановленном backend замените БД копией для восстановления. Не копируйте активную SQLite БД без её WAL; для живой копии нужен sqlite backup API. Удаление БД обнулит прогресс — обычный setup этого не делает.

## Проверки

Windows (из корня; на macOS замените путь Python на `.venv/bin/python`):

```powershell
Push-Location backend
..\.venv\Scripts\python -m alembic upgrade head
..\.venv\Scripts\python -m alembic check
..\.venv\Scripts\python -m pytest -q
Pop-Location
Push-Location frontend
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:e2e
Pop-Location
.\.venv\Scripts\python scripts/check_privacy.py
```

Перед E2E остановите обычные серверы на 8000/5173. Playwright запускает свои серверы и временную БД, не меняя учебный прогресс. Тесты браузера проверяют reload, тему, мобильную ширину и запрет доступа к приватным путям. Результаты фактического запуска: [VALIDATION.md](docs/VALIDATION.md).
